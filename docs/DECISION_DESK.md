# Decision Desk (읽기 전용 판단 작업대)

Glance 상단에 있는 작은 읽기 전용 작업대. 머리글+저장소 고르기 줄+
두 열(판단 목록·선택된 읽기 창)로 읽는다. 여러 저장소에 흩어진
질문(`question`)·이슈 검토(`issue-review`) 중 지원되는 결정 후보를
지원 목록에 모아 보여준다. `prepare-retry`·`joint-retry`·`external-pr`
등 다른 종류는 결정 후보가 아니라 전체 목록에서 따로 확인할 수 있다.
목록 행의 제목은 두 줄 발췌이며, 선택된 읽기 창에는 전체 제목과
질문 전문(제목과 다를 때만)을 그대로 보여준다. 같은 문장이면
되풀이하지 않는다. 판단·실행·게시는 하지 않는다. 답하기·승인·
재시도는 기존 실행 기록(`/work/<run-id>`) 흐름에서 그대로 한다.

## 데이터 계약

- 목록: `GET /api/decisions?repo=` → 스냅샷 바이트 그대로 투영.
  각 항목 `id = repo:kind:ref`. 제목은 요약 발췌(`title_excerpt`,
  `title_is_excerpt: true`)이며 전문이 아니다. 지원 목록에 든 항목 수,
  전체 요약 항목 수, 막힌 작업 수를 각각 따로 센다(서로 다른 모집단).
  지원하지 않는 종류는 전체 목록(저장소별 현황)에서 종류·수·원문
  위치와 함께 둔다.
- 상세: `GET /api/decision/detail?repo=&id=` → 선택된 1건만 저장된 실행
  기록에서 읽는다. 전체 질문문, 기록 신원(지문·base/work), 단계 상태,
  원문 이슈 링크(숫자 이슈 + 등록된 owner/repo가 있을 때만)를 돌려준다.
- 신원 대 개정: `id`는 *어떤* 판단인지, `inputs`(질문 전문·지문·커밋·
  단계·계약 버전)는 *내용이 바뀌었는지*를 본다. 시각·나이·관측 카운터는
  비교에서 제외한다. 판단 대상이 아니면 `inactive`, 읽을 수 없으면
  `unknown`을 돌려주고healthy인 척하지 않는다.

## 읽기 동작

- 같은 경로의 조용한 폴링은 데스크 서브트리를 통째로 갈아엎지 않고
  머리글·목록·전체목록만 갱신한다. 내용 키가 같으면 읽기 창 DOM을
  그대로 두어 포커스·스크롤·펼침이 유지된다. 읽기 창 안의 요약
  펼침(기록·출처, 실행 단계)과 주·보조 길에 있던 초점은 내용이
  바뀌어 다시 그려도 같은 종류의 대상에 되돌아가고, 바깥 읽기의
  초점을 훔치지 않는다. 대상이 사라졌으면 같은 창의 읽기 제목으로만
  되돌아가며, 다른 판단의 행으로는 옮기지 않는다.
- 내용이 바뀐 선택 항목만 다시 읽어(해당 1건만 GET) 다시 그리고,
  바뀜 배지를 한 번 보여준다. 다시 읽기가 실패하면 읽던 내용은
  유지하고 실패 맥락과 다시 불러오기 버튼을 함께 보여준다.
  현재라고도, 근거가 바뀌었다고도 말하지 않는다.
- 새 선택·다른 경로가 오면 낡은 응답은 버린다(요청 세대·경로 검사).
- 로딩·실패·비활성 화면은 항상 다시 그린다(같은 행 재선택 시
  로딩이 영원히 남지 않게). 최신 요약에서 빠진 선택은 기록을
  지우지 않고 비활성 안내를 한 번만 보여준다(오류 문구와 같은
  말이면 되풀이하지 않는다).
- 좁은 화면(≤640px)에서는 선택 시 목록 고르기 줄·목록이 접히고
  읽기 창이 먼저 보인다(맨 위 목록으로 길이 자리에 붙는다).
  목록으로 돌아가면 출발점의 목록·바깥 스크롤과 행 포커스가 복원된다.
- 판 안의 모든 보이는 조작(주·보조 길, 요약 펼침, 뒤로·다시 읽기)은
  44px 이상 누름 높이를 지킨다.

## 한계

- 이 작업대는 결정 UX가 아니라 읽기 전용 정보다. 같은 입력에 대한
  재검토, 답변 일괄 적용, 새 워크플로는 없다.
- 이슈 링크는 숫자 이슈 + 등록된 GitHub slug가 확인될 때만 생긴다.
  Discussions/PR 기록은 이슈 링크로 둔갑하지 않는다.
- 기록된 제안(`suggested`)은 요약에 함께 온 문구이며, 모델이 새로
  검토했다는 뜻이 아니다. 보내기 전 확인이 필요하다.
- 다음은 아직 확인되지 않았다: 최종 HTTP 계약 검사, 전체/파이썬 3.9
  검사, 실제 등록 저장소의 회귀-수정-재검사 흐름, 네이티브 증명,
  전체 UI·24시간 주장. 이 작업대를 썼다고 해서 유지보수가 끝난 것은
  아니다.
