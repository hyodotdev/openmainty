# 이슈 원문 컨텍스트 (읽기 전용)

과거 실행 중 트리거 원문이 기록되지 않은 경우(`트리거 원문 기록 없음`),
실행 기록을 바꾸지 않고 현재 GitHub 이슈 본문·상태를 별도로 조회하는
작은 읽기 전용 기능이다. 대상: 숫자 이슈가 있는 과거 실행
(예: react-native-nitro-sound#856, run-42fd6a6a).

## 보장

- GET `/api/run/issue-content?repo=&run=` 은 저장된 캐시 읽기만 한다.
  네트워크를 쓰지 않으며 실행 기록·트리거·프롬프트·로그·증명을
  절대 바꾸지 않는다.
- 가져오기는 명시적 버튼의 POST
  `/api/run/issue-content/fetch {repo, run, confirm: true}` 한 번뿐이다.
  폴링·열람 중 자동 재시도하지 않으며, 전역 워커 리스를 잡고 바쁘면
  409로 아무 것도 시작하지 않는다.
- 각 관찰은 `issue_context/{owner}__{name}/issue-{N}-{fp16}.json` 에
  불변 저장되고, `issue-{N}-latest.json` 이 최신 포인터·마지막 성공
  (`last_success`: 관찰 ID+수집 시각)·마지막 시도 기록을 따로 관리한다.
  관찰 파일에는 수집 시각을 두지 않는다. 손상·위조·외부 기록은 읽을 때
  명시적 저장소 오류로 보고되고 바이트는 보존된다. 절대 치유·덮어쓰기하지
  않는다.
- 현재 관찰은 과거 트리거가 아니다. 저장 시각만 바뀐 재조회는 같은
  관찰을 재사용한다(`changed: false`). 성공한 적 없는 상태에서 실패하면
  "마지막 성공 읽기"를 주장하지 않으며, 실패해도 마지막 성공 읽기는
  그대로 보인다(수집 시각은 마지막 성공 시각). 새 관찰은 새 지문을
  받으며, 원본 실행 입력과 섞이지 않는다.
- repo/이슈는 저장된 실행+등록 프로필에서 서버가 결정한다. 실행 ID·저장소
  이름은 단일 안전 경로 요소여야 하며, 저장된 실행의 `id`·`repo`와 등록
  프로필의 `name` 을 다시 대조한다. 클라이언트가 보낸 번호·주소·슬러그는
  신뢰하지 않으며, 어긋나면 거부한다(일치하면 허용). 닫힌 이슈는
  유효한 현재 상태(닫힘)로 보여준다. 본문 없음(빈 문자열)과 읽을 수
  없음(오류)은 구분된다.
- 저장소가 비어 있을 뿐 기록된 시작 원문이 있는 실행과, 기록 자체가 없는
  실행을 구분해 안내한다. 포커스·펼침 상태는 새로고침 후에도 유지되며,
  늦은 응답은 다른 실행을 그리지 않는다.
- 댓글·라벨·노드 연결은 수집하지 않으며, UI에 "수집하지 않음"으로
  명시한다. 모델 호출은 없다.

## 범위 밖

- 원문 조회는 현재 GitHub 상태 확인일 뿐, 과거 실행의 재현·검증·리뷰가
  아니다. 모델 리뷰·승인·머지·공개 동작은 이 경로에서 수행하지 않는다.

## 타입 이슈 준비→등록 (prepare→fastcheck→APP-OWNED REGISTER)

숫자 이슈 후보를 의존성 후보와 같은 기계로 준비·검증·등록하는 흐름이다.
의존성 동작·기존 기록은 그대로 두며, 이슈는 구조적으로 다른 이름공간을
쓴다. `dep`/`target` 값을 흉내 내지 않는다.

- **입장**: 저장된 앱 소유 큐 기록 `kind == "issue-triage"` 와 일치하는
  `run_id`/`repo`/`issue`/`key`/`branch` 를 요구한다. 큐가 없으면 거부한다
  (run.issue + sourceKind 추측만으로 입장하지 않는다). 저장된 실행의
  `queue_key` 는 비어 있지 않은 정규 `repo#issue-번호` 여야 하며,
  없거나 비거나 어긋나거나 위조된 값은 거부한다. 이슈 번호는
  양의 ASCII 숫자 문자열이며, 등록 프로필의 소유자/저장소와 정확히 대조한다.
  모호·혼합·모순된 출처는 쓰기 전에 거부한다.
- **별도 통합 브랜치**: 원본 큐 소유 브랜치(예: `codex/next/issue-856`)를
  재사용하지 않는다. 앱 소유 새 브랜치
  `codex/review-issue-<번호>-<저장소/레인/이슈/run/batch 안정 다이제스트>` 와
  op 범위 result 경로를 쓰며, 원본 브랜치 HEAD·출처·인덱스를 바꾸지 않는다.
  기존 경로·브랜치 충돌 검사는 그대로 유지한다.
- **원본/통합 분리**: 등록 명세의 `source` 는 원본 후보
  (`store.run_dir(run_id)/work` + 원본 브랜치 + 기록된 원본 head/fp)에
  묶인다. 준비된 통합 결과(worktree/branch/head/fp + 동일 출처 fastcheck
  수신증)는 별도 바인딩으로 둔다. 원본 기대치가 없을 때 live 결과로
  대체하지 않으며, 그 반대도 하지 않는다. 원본 증명은 그대로 검증한다.
- **수신증**: 실제 fastcheck 기록 형태를 검증한다(최상위 head/fingerprint
  필드는 없다). 단계별 `head`/`fingerprint`·`argv`·`gate`·엄격 정수
  `rc 0`(bool 제외)·필수 `timed_out: false`, 설정 단계 순서 일치, op
  `fastchecks` 게이트 통과(worker 확인 + 최종 영수증 SHA)를 확인한다.
  로그는 표준 경로 `<op>.fastcheck.<pos>.log` 의 읽히는 바이트와 기록
  SHA 로 묶으며, 임의 경로는 거부한다. 중첩 프로필 `fastcheck.steps`
  를 쓰며, consumer extra 단계는 실제 기록 형태만 허용한다(head/fp
  요구 금지).
- **등록**: 렌더된 등록 컨트롤이 op+confirm 만으로
  `POST /api/integration/register` 를 호출한다. 전역 리스→op락→저장소
  잠금 순서로 잠그고 import 커밋 끝까지 유지한 뒤 finally 로 해제한다.
  완료된 op·정확한 결과 출처·현재 fastcheck 수신증을 등록 전과 재사용
  전에 모두 재확인한 뒤 서버에서 명세를 만들어 지원 import 로 등록한다.
  동일 기대치는 같은 배치를 재사용하고, 어긋나거나 기록이 손상되면
  409 로 바이트를 보존한다. 빈 객체 `{}`·빈 배열 `[]`·깨진 JSON 등도
  부재로 취급하지 않고 거부한다.
- **키/평가**: 이슈 기본키는 `issue:repo:lane:number` 이며
  의존성 키와 충돌하지 않는다. `primary_result_key` 는 잘못된 기록을
  조용히 건너뛰지 않고 명시적 NOTREADY 로 만든다. UI 목록은 실제
  패키지/버전 또는 이슈 번호·레인을 먼저 보이고, 등록 버튼은 타입 이슈
  준비+실행된 수신증이 있을 때만 보인다.
- **테스트**: `tests/test_integration_prepare_issue.py` 가 입장·검증자·키·
  원본/통합 분리·명세·등록·경로를, `test_dashboard_shell.py` 와
  `test_batches_api.py` 가 표시·투영 계약을, 오프라인 임시 Git·새 격리
  홈으로만 검증한다(원본!=결과, 원본 브랜치 선점 포함).
- **Stage17 충돌 조사(읽기 전용)**: 막힌 타입 이슈 준비
  (`status blocked`, 결과 head/fp 비어 있음, 작업트리 제거됨)에 대해
  별도 `issue_recovery/<op>/` 네임스페이스에 불변 입력·보고·시도만
  기록한다. 부모 op·원본 run·증명은 바이트 그대로 둔다. 모델 입력은
  고정 ref 의 Git blob 에서 읽은 실제 전송 범위만 쓰며, 생성물·대용량은
  해시·크기·사유와 함께 생략 목록에 남긴다(생략이 전달 완료가 아님).
  `issue.repo` 는 등록 로컬 이름이며 정식 GitHub 슬러그와 별개다.
  40-hex 커밋 ID 와 64-hex 내용 지문을 엄격히 구분한다. 큐·run·프로필·
  증명·베이스 바인딩은 batches 공유 검증자를 호출로만 재사용한다.
  모델 입력은 고정 ref 의 Git blob 에서 읽은 실제 전송 범위만 쓰고,
  전송 텍스트·바이트·범위를 스냅샷에 보관한다. 전송·요청·인용·생략 범위를
  구분하고, 동일 모델 입력은 동일 입력을 재사용한다. 모델 실행 전·후에
  부모 SHA·원본 3-way ref(원본 baseCommit·원본 후보 head·선택 베이스)·
  전송 범위로 지문을 재검증하고, 바뀌면 stale 로 버린다. 모델 출력은
  실제 Muse JSONL(terminal/delta)과 Discussion 추출기를 쓰고, 인용은
  전송된 경로·ref·줄 범위에 인용문을 대조한다.
  `GET /api/integration/recovery?op=` 는 캐시 읽기만 하고 잠금을
  잡지 않는다. 실행 중에도 같은 최신 `job_id`·시도별 `job_live` 로
  읽기 전용 관찰이 가능하며, 쓰기는 하지 않는다.
  `POST /api/integration/recovery/review` 는 `{op, confirm: true}` 로
  한 번의 읽기 전용 구독 검토를 시작한다. 리스→op락을 먼저 잡는다.
  입력 생성 전의 바쁨(리스 점유·op 사용 중)은 기록 없이 409 로
  종료한다. 입력 생성 뒤의 슬롯 부족(`_job_new` None)은 입력·시도·
  latest 를 시작 실패(error) 터미널 상태로 보존하고 409 로 종료하며
  리스를 해제한다 — "기록 없음"이 아니다. 슬롯 확보 뒤의 시작 실패
  (취소 이벤트 분실·스레드 시작 예외)는 같은 시도·latest 보존에 더해
  대시보드 작업 슬롯도 done/rc1/ended_at 터미널로 닫고 500 으로
  종료한다. 시작 전 취소는 모델을 호출하지 않고 130/cancelled 로
  기록된다. 진짜로 실행 중인 동안의 두 번째 POST 역시 409 로
  거부되며 중복 모델 실행은 없다.
  `started/reused/attached/job_id/reason` 응답 필드가 명시적이고,
  동일 입력은 재사용하고, 실패한 시도는 보존된 채 한정 재시도한다.
  기록 이름은 생성 규칙(`input-…`·`attempt-rr-…`·`report-…`·
  `latest.json`)과 엄격히 대조하고, 경로 이탈·심볼릭링크·외부 파일을
  거부한다(읽기·쓰기 모두). 저장소 손상·보고서 분실은 명시적 오류이며,
  바이트는 보존된다. done 포인터는 검증된 현재 보고서일 때만
  current 이고, 바인딩 실패(부모·원본·베이스 변경·읽기 불가) 시에는
  latest 표시만 stale 로 투영하고 `binding_error{코드, 메시지}` 와 함께
  원래 입력·시도·보고서를 이력으로 검사 가능하게 둔다. 지문은 전송
  프롬프트 바이트뿐 아니라 파일별 blob·전체 크기·partial·중간 생략
  메타데이터까지 묶어, 정보 필드만 바뀌어도 재사용되지 않는다.
  검사가 실행되지 않은 막힘은 `not_run(준비 충돌로 미실행)` 으로 보이고,
  손상·오래됨·읽기 실패 수신증은 오류로 둔다. 일반 done 준비의 미실행은
  충돌 문구를 달지 않는다. 준비된 출처가 없으면(결과 head/fp 없음 —
  잔여 경로 문자열은 존재가 아니다) 추가 수정 요청을 비활성화하고
  조사 검토를 먼저 안내한다. 파생 준비는 별도 승인 전까지 제공하지
  않는다. UI 는 전송 근거(제한된 코드 창 포함)·생략·인용·입출력 연결을
  접힘 뒤에 보이고, 실행 중엔 검토 버튼을 비활성화하며, 같은 op 의
  늦은 응답도 그리기 세대+연결 상태로 버리고, 읽던 접힘·포커스·스크롤을
  보존한다. 빈 조사 응답은 읽기 실패로 표시하고, 다시 읽기는 실패를
  상태 줄에 남긴다.
- **원본 이력 검증(v6)**: 구조적 부모 실패(wrong-kind·not-blocked·
  형식 오류·손상)는 이력이 아니라 typed 오류로 종료한다. 살아 있는
  바인딩이 stale/unreadable 인 구조적 정상 부모에 한해, 저장된 원본
  정체성(원본 run SHA·등록 origin·타입 이슈·ref 바인딩·스냅샷 지문)과
  연결이 완전히 증명될 때만 과거 기록을 보여준다. `current=false` 는
  귀속이 아니라 표시 조건이며, 저장된 856 라벨 아래에 drift 된 857
  부모를 붙이지 않는다. 과거 표시는 저장된 원본 issue/candidate/base/
  error·바인딩 실패·전체 시도 수(`attempt_total`, 처음 20건만 투영)를
  쓰며, fastcheck 는 검증된 원본 op 별 수신증만 읽고 빈 식별자로
  not_run/error 를 꾸미지 않는다. 저장소 경로는 lexical 요소부터
  검증하며, 디렉터리 내 별칭·조상 별칭·끊긴 링크·순환도 거부한다.
  읽기·쓰기 모두 같은 규칙을 쓰고 거부 시 바이트를 그대로 둔다.
  과거 스냅샷 변조·외부 체인 연결도 독립적으로 거부된다.
- **공유 원본 체인 검증(v7, 계약 2)**: refs 맵·표시 원본 실패/충돌
  범위·partial 범위는 지문에 함께 묶인다. refs 맵만 바꿔도, 표시
  원본 문구만 바꿔도 재사용되지 않는다. 계약 2 이전 기록은
  검증 불가(unverifiable)로 보존되며 치유·이관하지 않는다.
  latest→owner→input 소유 검증은 queued/running/error 등 모든
  수명 상태에 동일하게 적용되며, 완료됐지만 보고서가 없는 latest
  는 손상이다. worker 는 전송 전에 저장 정체성·소유권을 먼저
  검증하고, 전송 중 변경은 성공 저장 전에 재검증한다. 구조적
  실패·잘못된 종류·잘못된 식별자는 어떤 이력으로도 둔갑하지
  않는다. 유효한 새 입력은 옛 완료 기록을 보존한 채 새 입력·시도로
  허용되며, corrupt 로 오인하지 않는다. fastcheck 식별자 없이는
  unknown 으로만 보고한다.
- **전체 서술자 바인딩(v8, 계약 3)**: 지문은 head/지문뿐 아니라 전체
  원본 candidate 서술자(head·fingerprint·branch·worktree)와 전체
  베이스 서술자(batch·lane·head·fingerprint·checkout)를 함께 묶는다.
  branch·checkout 만 바꿔도 재사용되지 않으며, 계약 2 이하 기록은
  검증 불가(unverifiable)로 보존되고 치유·이관하지 않는다. 변조된
  저장 입력은 전송 전에 typed 502/corrupt 로 거부되며 모델을
  호출하지 않는다(전체 호출 수명 동안 mock 미호출로 검증). 공유
  픽스처 헬퍼(`_done`·`_rewrite_op`)는 `RecoveryFixtureMixin` 에만
  두며, 테스트 클래스 상속으로 중복하지 않는다. 변조 케이스는
  변조된 바이트 보존과 원본 바이트 불변을 함께 검증한다.
