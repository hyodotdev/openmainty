# PR 검토함 (읽기 전용 PR 리뷰)

이 문서는 앱 조작법이다. PR을 게시·병합·라벨 변경하지 않는다.

## 무엇이 가능한가

- 저장소 `PR` 탭: 사람 PR을 먼저, 봇 PR은 접힌 목록으로 본다.
- PR을 선택하면 원문(제목·본문·diff·검사·스레드)을 읽고,
  `원문 가져오기`(모델을 쓰지 않음)로 최신 내용을 가져온다.
- `읽기 전용 검토 시작`으로 앱 소유 검토 작업을 시작한다.
  모델은 읽기 전용 플래그(`--disable-write/--disable-shell/--disable-web-tools`,
  단계 상한, 키 없는 구독 실행)로만 동작하고, 결과 JSON이
  검증(허용된 근거 URL·보낸 소스·권장 등급)을 통과해야만 기록된다.
- 검토 결과에는 요약·발견·GitHub 라벨(원문 표시)과 앱 제안 라벨(미적용),
  인용한 근거, 비공개 회신 초안(게시 안 함), 권장
  (`adopt-external | keep-local | needs-changes | needs-info`)이 남는다.

## 닫는 이슈·실행 기록 비교

PR이 닫는 이슈마다 `닫는 이슈·실행 기록 비교`에 다음이 나온다.

- GitHub 이슈 원문 링크.
- 앱 실행 기록(최신): 실행 id, 만든 시각, head/fingerprint, 파일 목록.
- PR 파일 목록과 실행 기록 파일 목록의 개수 비교.
  개수가 다르면(예: PR 2건 vs 기록 1건) 그대로 표시되며,
  어느 한쪽이 없으면 비교 불가로 표시한다. 현재·과거 구분은
  실행 기록을 열어 확인한다.

## 정직한 상태 읽기

- `미가져옴`: 목록에는 있지만 원문을 아직 가져오지 않음.
  `원문 가져오기` 버튼으로 가져온 뒤 검토가 가능하다.
- `부분 수집/확인 필요`: 가져오지 못한 섹션이 있다는 뜻.
  없는 섹션을 빈 성공으로 표시하지 않는다.
- 검토 중에는 화면이 자동 새로고침되며, 읽던 위치·열어둔 항목·입력 중인
  근거 선택은 유지된다.
- `모델 사용 불가`이면 검토 시작 버튼이 비활성화되고 이유가 표시된다.
  가져오기와 저장된 기록 읽기는 계속 된다.

## 근거 전달 방식(모델이 실제로 본 것)

- 수집된 PR diff 전체가 상한 안에 들면 그대로 전달된다.
  상한을 넘기면 잘린 사실과 바이트 수가 부분 기록에 남는다.
- 바뀐 파일은 diff hunk 주변의 줄 구간만 보내며,
  각 구간 머리말에 정확한 줄 구간·전체 줄 수·바이트 수가 적힌다.
  창 밖에 있는 코드는 검증되지 않은 것으로 표시된다.
- 전달 묶음에는 `delivery_version`과 diff·창별 해시가 함께 기록되며,
  같은 입력은 같은 시도로 합쳐지고 전달 내용이 바뀌면 새 시도가 된다.
  전달 방식 변경이 원문 변경으로 둔갑하지 않는다.

## 시도 기록과 근거 확인

- 검토됨 상태도 시도 기록에 현재 시도의 rid를 남긴다.
  `시도 보기` 버튼으로 현재·과거 시도의 근거·부분 기록을 연다.
  저장된 기록이 없거나 깨졌거나 다른 PR의 것이면 오류 행으로만
  보이고 버튼이 생기지 않으며, 원래 바이트는 그대로 둔다.
  검토됨 기록은 요약·판단근거·라벨·권장·권장근거·회신키와
  다이제스트 지문을 갖춘 경우에만 근거로 연결된다.
- 목록 조회는 시도 근거 파일을 읽지 않는다. 근거 확인은
  PR을 선택한 상세 조회에서 이루어진다.
- 인용 근거는 뜻있는 짧은 이름(PR 원문·스레드 위치·검사 이름)으로
  보이며, 전체 URL은 링크와 title에 그대로 유지된다.
- 앱 제안 라벨은 한국어 값으로 보이지만 원시 영문값이 title에 남고,
  GitHub 적용 라벨과는 별도로 미적용 참고용이다.

## 한계

- 인라인 스레드·검사는 페이지당 상한이 있어 잘릴 수 있으며,
  잘리면 부분 기록에 남는다.
- 댓글에 링크만 있고 가져오지 않은 URL은 근거로 인용할 수 없다.
- 이 검토는 읽기 전용 분석이며, 기기 실행·네이티브 검증을 대신하지 않는다.
  부분 보고서의 결정 요약은 병합 준비가 아니라 재검토가 다음 행동이다.
- 다른 화면에서 먼저 가져오지 못한 오류가 남아 있으면, 목록이 바뀌거나
  시간이 지난 뒤 일반 조회로 한 번 다시 가져와 회복한다.
  자동 재시도·모델 재실행은 하지 않는다.
